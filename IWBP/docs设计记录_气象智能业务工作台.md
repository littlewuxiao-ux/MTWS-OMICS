# 气象智能业务工作台 设计记录（基于当前 `index.html`）

更新时间：2026-05-29（公司 FOC 对接进行中，待 IT 网络）  
基线文件：`d:\weather agent\V2\index.html`（静态单文件原型）

## 1. 目标与定位

本原型用于验证“监测 - 处置 - 分析”一体化工作台的信息组织与交互闭环，当前以静态前端演示为主，包含部分真实外部数据拉取能力（METAR/TAF、Open-Meteo），并保留企业系统集成接口位（登录、审核、外部通讯同步等）。

## 2. 整体信息架构

### 2.1 顶层视图

- 首页（`view=home`）：三入口导航（告警屏 / 处置屏 / 分析屏）
- 告警屏（`view=monitor`）：默认视图，重点展示**天气预警**与**报文监控**（METAR/TAF）
- 处置屏（`view=action`）：围绕预警发布、审核、状态推进
- 分析屏（`view=analysis`）：上方 **天气分析**（外部站点集合）+ 下方 **要素分析**（机场预报时序）

### 2.2 页面主区域卡片（Card）

- Card 1：业务提醒
- Card 2：AI 对话窗口（占位交互）
- Card 3：天气提醒模块（短临预警 + METAR/TAF 报文监控）
- Card 4：天气分析模块（上方 **天气分析** 外部站点 + 下方 **要素分析** 预报时序）
- Card 5：预警发布（编辑、提交审核、待审核列表）
- Card 6：实时检验（准确率占位指标）

## 3. 关键模块设计

### 3.1 账号与角色

- 支持账号切换和角色切换（值班员 / 带班）
- 角色影响操作权限：带班可执行“审核通过/驳回”，值班员仅提交
- 通过 `localStorage` 保存部分账号相关状态（例如站点收藏）

### 3.2 视图导航与新标签页打开

- 顶部按钮支持“一键打开告警屏/处置屏/分析屏”
- 卡片级支持“在新标签页打开”
- URL 参数驱动视图状态（`?view=home|monitor|action|analysis`）

### 3.3 天气提醒模块（核心）

#### A) 短临预警区

- 预警机场列表（示例站点）
- 预警滚动条（ticker/marquee）
- 支持“查看全部生效预警”弹窗

#### B) 报文监控区（METAR + TAF）

- 分为 METAR 实况列表与 TAF 预报列表
- 支持刷新、展开全部、详情弹窗
- 支持筛选：白名单、异常优先、国内/国际等
- 对报文进行风险等级判断并着色（严重/告警/注意/正常）
- 详情页支持「原文 + 解析翻译（词汇注释）」
- **专屏布局**：告警屏仅保留「天气预警 + 报文监控」两栏，纵向占比约 **4 : 6**，报文区获得更多可视高度

#### C) 要素分析区（已迁至分析屏 Card 4）

- 站点输入后查询机场要素时序
- 模态窗支持「简单要素 / 全量要素」切换
- 支持模型切换：`auto` / `gfs` / `ecmwf`
- SVG 绘制多要素时序图（风、温度、云量、降水等）

### 3.4 天气分析模块（分析屏 Card 4）

分析屏自上而下分为两大块，与告警屏 subcard 风格一致。

#### A) 天气分析（上部 · 分类站点导航）

- **交互**：点击卡片在新标签页打开；不支持 iframe 内嵌（外部站策略）
- **分类**：常用、我的收藏、国家/省市官方、国际官方、数值预报、雷达、卫星、闪电、空气污染、火山灰、商业气象、公司内部（示例占位）、工具、国内/国际综合
- **搜索**：按名称、说明、域名过滤
- **收藏**：按账号 `localStorage` 持久化；卡片 ☆ 一键加入收藏；支持手动添加与重置
- **站点目录**：内置 `WX_NAV_SITES` 数组，后续可改为 JSON / 配置接口

#### B) 要素分析（下部）

- 与 3.3-C 同一模块；位于分析屏底部条带
- 站点输入后查询机场要素时序；弹窗内切换简单/全量要素与 Open-Meteo 模型

### 3.5 预警发布与审核流

- 发布类型：天气预警 / 时段预报
- 支持接收对象选择
- 支持“同步到丰声群（模拟）”开关
- 提交后进入待审核列表
- 带班可审核通过/驳回；通过后可自动补充到短临预警池（演示）

### 3.6 实时检验

- 当前为占位指标（准确率进度条）
- 预留接入真实检验统计口径

## 4. 数据来源与当前实现状态

### 4.1 当前已接入/可拉取

- METAR/TAF：通过 AWC 接口拉取并标准化
- 机场要素时序：使用 Open-Meteo 预报接口（失败时有模拟数据兜底）
- 机场白名单：支持 API / 静态文件 / 默认列表三级回退

### 4.2 当前仍为模拟/占位

- 登录态校验（存在 `login.html` 跳转逻辑，但未与企业 SSO 真正打通）
- 丰声同步仅为模拟开关，未做真实推送与回执
- 实时检验指标为演示值，未接入真实数据管道

## 5. 交互与体验要点

- 多个弹窗（预警全文、报文详情、报文展开、要素图）形成“总览 -> 细节”钻取链路
- Toast 提示统一反馈操作结果（保存、切换、失败提示）
- 报文风险色彩与标签统一，提升值班场景识别速度
- 首页三入口与分屏跳转适配“不同岗位专屏使用”

## 6. 当前技术实现特征

- 单文件架构：HTML + CSS + JS 内联，便于快速演示和离线分发
- 以原生 JS 为主，无框架依赖
- 数据、规则、UI 事件高度集中，迭代快但后期维护成本会升高

## 7. 已识别的主要风险

- 代码集中在单文件，后续功能增加会导致维护难度和回归风险上升
- 外部接口稳定性与跨域/网络策略对实时能力影响较大
- 角色权限目前在前端控制，生产环境需后端强校验
- “模拟能力”与“生产能力”边界尚未完全显式化

## 8. 下一阶段建议（从原型到可上线）

### 8.1 架构拆分

- 拆分为：`layout`、`monitor`、`action`、`analysis`、`shared`
- 抽离数据层（API client、数据标准化、错误处理）
- 抽离规则层（告警规则、报文解析词典、等级判定）

### 8.2 真实系统对接优先级

1. SSO 登录与权限模型（角色/岗位/组织）
2. 预警发布审核后端化（审计留痕、状态机）
3. 丰声机器人或消息接口对接（重试、幂等、回执）
4. 数据源治理（缓存、限流、熔断、降级）

### 8.3 质量保障

- 增加关键流程自动化测试（提交流程、审核流程、告警判级）
- 为外部接口加入可观测性（请求成功率、时延、错误分类）
- 建立“演示模式 / 生产模式”开关，避免误发布

  - **A37–C46**：每日 **03:00–09:00** 班次工作项。

### 11.2 时限 T、提醒与质检口径

- **T 表示完成时限（截止时间）**：该项须在 **T 之前**完成（不含 T 的瞬时边界以实现时约定为准，建议「当前时间 ≥ T 且未完成」即判超时）。
- **阶梯提醒**：仅当该项尚未在界面标记「已完成」时，在 **T−30 分钟、T−15 分钟、T−5 分钟** 各提醒一次（均在截止时间之前）。
- **超时与补做**：超过 T 仍未完成 → 记 **未按时完成** 并归档；允许后续补做并在界面确认完成，但须**保留**未按时完成记录，并记录 **超时分钟数**（或 `missed_at` 与 `first_completed_at` 推导），供质量人员抽查与导出。
- **完成认定**：仅由值班员在界面点击「已完成」，**不对接**外部业务系统自动判定。

### 11.3 固定模板与修订接口

- 检查单按日内容**固定**，仅按 **三个班次**切换展示与调度逻辑。

**航班接口 Body 约定**：`startTime`=现在−24h，`endTime`=现在+48h，`excludeCancel`=true，`excludeHaveAta`=true（毫秒时间戳）。

**报文类型**：`wtype` — `SA`=实况 METAR，`FC`/`FT`=预报 TAF。

**实况结构化字段**（接口 3，`obj[]`）：除 `content` 外含 `windDirection`、`windSpeed`、`visibility`、`cloud1`、`temperature`、`airPressure`、**`ryg`**（20 位字符串，疑为公司判色/预警编码）、`proWeather` 等——**判级应优先用公司字段，而非 AWC 自解析**。
