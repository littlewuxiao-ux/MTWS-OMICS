# 席位电脑 × 个人笔记本 协作说明

> 个人笔记本：**Cursor 改代码**（不必装无边界）  
> 席位电脑：**公司 FOC 联调**（已在公司网，一般可直接访问 `*.sfcloud.local`）

---

## 1. 目录约定

请在 **席位** 与 **笔记本** 使用 **同一套文件夹路径**（减少拷贝后路径不一致问题）。

| 机器 | 建议路径（按你实际专用文件夹为准） |
|------|--------------------------------------|
| 个人笔记本 | `d:\weather agent\V2` |
| 席位电脑 | **同名路径**，例如 `d:\weather agent\V2`（放在你的专用文件夹下） |

首次在席位部署：把整个项目文件夹 **完整复制** 到席位同名目录（或 Git clone 一次）。

---

## 2. 什么要同步、什么不要

### 要带回笔记本（改代码用）

- `index.html`
- `docs/`（含本文件、设计记录）
- `tools/`（`dev-server-proxy.cjs`、`sf-foc-ping.cjs` 等）
- `data/` 下 **非密钥** 文件（如 `icao-whitelist.json`、检查单 json 等）
- `package.json`（若存在）

### 只在席位维护（勿拷回家、勿提交 Git）

- `data/sf-foc-config.local.json`（含 systemKey / accessKey / **token**）
- 席位上单独配置；回家若要测 FOC 再在本机扫码生成

### 可选：用 Git 同步代码

- 密钥文件已在 `.gitignore` 排除 `data/sf-foc-config.local.json`
- 流程：`笔记本 push` → `席位 pull` 测通 → 若有席位小改再 `push` → 笔记本 `pull`

## 3. 上班日（席位）— 只测 FOC

在 **专用文件夹** 打开 PowerShell：

```powershell
cd "d:\weather agent\V2"
node tools/sf-foc-ping.cjs
```

看到 **DNS: 成功** 后：

```powershell
npm start
```

浏览器打开：`http://localhost:8787/index.html`

**检查：**

1. 告警屏 → 预警机场 → 点四字码 → 弹窗 METAR/TAF，底部 **「公司 FOC」**
2. 报文监控 → 刷新实况/预报 → 底部 **「来源 公司 FOC」**

**token 过期时（席位上，生产/UAT 通用）— 主流程：首页扫码**

CAS token 约 **12 小时**过期。过期后工作台会自动回到 **首页**，上方出现 **「丰声扫码续登」** 面板（无需找 bat 文件）：

1. 确认 **`start.bat` 已在运行**（浏览器能打开 `http://localhost:8787/index.html`）
2. 打开或刷新首页 → 出现二维码
3. 手机 **丰声 Next** 扫码确认
4. 提示「续登成功」后，点 **告警 / 处置 / 分析** → 报文监控应显示 **「来源 公司 FOC」**

扫码成功后 token 自动写入 `data/sf-foc-config.local.json`（与 bat 效果相同）。

**备用方式**（本地服务起不来、或首页不出二维码时）：

```powershell
cd /d "d:\weather agent\V2"
# 双击 renew-cas-token.bat，或：
python tools/cas_login.py
```

续登完成后在浏览器 **Ctrl+F5** 强刷一次。

**测完如有问题：** 截图或复制报错全文，记在记事本里带回笔记本。

**下班拷回笔记本：** 只拷 **代码与文档**（见 §2），不必拷 `sf-foc-config.local.json`。

## 5. 常见问题

| 现象 | 原因 |
|------|------|
| 席位 `sf-foc-ping` DNS 失败 | 席位未连公司网 / 需问 IT 是否要额外认证 |
| 笔记本 AWC 有数据、FOC 报错 | 正常；FOC 只在席位（或开无边界）测 |
| 席位测通、笔记本页面仍失败 | 笔记本未同步最新 `index.html`，或笔记本未开 npm start |
| token 过期 | 首页 **丰声扫码续登**（主）；备用 `renew-cas-token.bat` |
| 首页无二维码 / 扫码失败 | 看「气象工作台」黑窗口有无报错；确认 `npm start` 在跑；再试备用 bat |
| 续登成功但仍是演示数据 | Ctrl+F5 强刷；告警屏点「刷新实况/预报」 |

## 6. 从笔记本同步代码到席位后，要不要「重启本地服务」？

**本地服务** = 席位上跑工作台的 Node 程序（`start.bat` → `npm start`），监听 **8787** 端口，负责转发 FOC 接口、首页扫码续登 API 等。

| 改了什么 | 席位上要做什么 |
|----------|----------------|
| 只改了 `index.html`（页面样式/逻辑） | 浏览器 **Ctrl+F5** 强刷即可，**不必**重启服务 |
| 改了 `tools/dev-server-proxy.cjs`、`tools/sf-foc-cas-web.cjs` 等 **后端脚本** | **需要重启** 本地服务，新接口才会生效 |
| 第一次部署 / 很久没开席位 | 双击 **`start.bat`** 启动即可 |

**重启操作（约 30 秒）：**

1. 找到运行 `start.bat` 的 **命令行窗口**（标题常含「气象工作台」或停在 `npm start`）
2. 在该窗口按 **Ctrl+C** 停止，或直接 **关掉窗口**
3. 再双击项目根目录的 **`start.bat`**
4. 等窗口里出现监听 8787 的提示后，浏览器打开 `http://localhost:8787/index.html`

若找不到窗口，可在 PowerShell 执行（项目目录下）：

```powershell
cd /d "d:\weather agent\V2"
tools\launcher-stop-workbench.bat
start.bat
```

`launcher-stop-workbench.bat` 会结束占用 8787 的进程，然后重新 `start.bat` 即可。

> **说明：** 平时值班 **不用** 每天重启；只有 **更新了后端代码** 或 **服务异常/端口占用** 时才需要。
