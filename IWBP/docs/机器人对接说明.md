## 2. HTTP 接口

| 用途 | 方法 | URL |
|------|------|-----|
| 拉待发 | GET | `/api/publish/outbox?pending=1&enrich=1` |
| 拉某类待发 | GET | 加 `&type=period` / `brush` / `alert` / `tc` |
| 拉某时段预报 | GET | 加 `&type=period&slot=h4`（或 `h12` / `h8`） |
| 标记已推送 | POST | `/api/publish/outbox` |
| 读取 @ 规则 | GET | `/api/publish/robot-config` |

### 2.1 拉待发（推荐 enrich=1）

```http
GET /api/publish/outbox?pending=1&enrich=1
```

返回每条除 `text` 外，还有：

- `contentKind`：`period` / `brush` / `alert` / `tc`
- `contentLabel`：中文类型名
- `targetGroup`：航空气象信息通报群
- `mentions`：建议 @ 列表（含 `label`、`nextUserId`，**userId 待 IT 填写**）
- `periodSlotId`：时段预报槽位 `h4` / `h12` / `h8`（仅 type=period）

### 2.2 标记已推送

```json
POST /api/publish/outbox
Content-Type: application/json

{
  "action": "mark-pushed",
  "ids": ["po-xxx"],
  "pushedBy": "天气助手"
}
```

## 3. 四类通报 · 发群与 @ 规则

目标群：**丰声 Next · 航空气象信息通报群**。

### 3.1 时段预报（type=period）

与工作台「预报发布 → 时段预报」一致，**每日 3 份**。  
**发布截止 = 有效时段开始时刻（北京时）之前**，不是有效时段结束时刻。

| slotId | 标题 | 有效时间（北京时） | 须在此前发布 |
|--------|------|-------------------|--------------|
| `h4` | 未来4小时天气预报 | 当日 04:00–08:00 | **当日 04:00 前** |
| `h12` | 未来12小时天气预报 | 当日 08:00–20:00 | **当日 08:00 前** |
| `h8` | 未来8小时天气预报 | 当日 20:00–**次日** 04:00 | **当日 20:00 前** |

跨日说明：`h8` 的有效时段跨到次日 04:00，但**发布截止仍是当日 20:00**（有效时段起点），不是次日 04:00。

- **@ 对象**：无（发群即可，**不 @ 任何人**）
- **机器人策略**：在每个**发布截止时刻**前开始轮询（建议提前 3 小时起，每 10 分钟一次），直到抓到、发群、mark-pushed

示例：

- 04:00 前 → `GET ...?pending=1&type=period&slot=h4&enrich=1`（轮询窗口约 01:00–04:00 北京时）
- 08:00 前 → `slot=h12`（约 05:00–08:00）
- 20:00 前 → `slot=h8`（约 17:00–20:00）

## 6. 兜底设计（防止「入池就算发完」）

工作台与服务端约定：

1. **入池 ≠ 已发群**：值班员点「保存并复制」后，状态为 `pushedToNext: false`（待推送 Next）。
2. **工作台兜底提醒**（`预警和预报发布` 卡片顶部）：
   - **漏发风险**：已过截止时刻，今日该份预报/梳理从未成功推送
   - **卡在池里**：已入池但超时仍未推送（机器人离线或未抓到）
   - **临近截止**：提醒准备手动发群
3. **存档按钮角标**：显示待发条数；有超时/漏发时变红。
4. **人工兜底路径**：存档详情 → **复制正文** → 手动粘贴 Next 群 → **标记已推送 Next**。
5. **API 查询超时待发**：`GET /api/publish/outbox?pending=1&overdue=1`

机器人侧仍应：抓取 → 发群 → `mark-pushed`；工作台兜底是机器人失败时的最后一道防线。
