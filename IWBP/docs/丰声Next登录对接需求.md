# 气象智能业务工作台 · 丰声 Next 登录对接需求（第一阶段）

**提出方：** 气象服务席  
**应用名称：** 气象智能业务工作台（Web，本地/内网部署）  
**访问方式：** 席位浏览器打开 `http://localhost:8787/index.html`（试点）；正式上线可为内网固定 IP/域名  
**目标：** 值班员通过 **丰声 Next 扫码** 或 **工号+密码** 登录后使用工作台，替代当前演示用本地登录。

---

## 1. 我们需要什么

| 能力 | 说明 |
|------|------|
| **扫码登录（优先）** | 工作台跳转 Next/钉钉授权页 → 用户扫码确认 → 回调带回身份凭证，工作台识别工号、姓名 |
| **工号+密码登录（备选）** | 若 Next 提供账号密码接口或统一 CAS，可与扫码二选一或并存 |
| **登出** | 清除会话，回到登录页 |
| **身份字段** | 至少：`工号（empId）`、`姓名`；如有 `部门/岗位` 可一并返回（用于后续权限扩展） |

**说明：** 第一阶段 **不对接** Next 群消息推送、机器人；仅 **登录鉴权**。发布内容仍由值班员在工作台编辑后 **复制到 Next 手动发布**。

---

## 2. 技术形态（供 IT 选型）

工作台当前为 **浏览器 + Node 本地代理**（`npm start`），无独立 Java 后端。建议任选一种对接方式：

**方案 A（推荐）：OAuth2 / 钉钉开放平台扫码**

- IT 在钉钉/丰声 Next 侧创建 **企业内部应用**
- 提供：`AppKey`、`AppSecret`、授权回调地址（Callback URL）
- 工作台登录页跳转授权 → 回调带 `code` → 服务端（或 Node 代理）换 `access_token` 与用户信息

**方案 B：CAS / 统一身份（若公司已有）**

- 提供：登录入口 URL、回调参数、ticket 校验接口、用户信息字段说明
- 与现有 FOC 气象接口所用 token 体系是否同源，请 IT 一并说明

**方案 C：Next 提供的 H5 免登 / 内嵌凭证**

- 若 Next 支持在指定内网页注入已登录身份（Cookie / Header / JSBridge），请提供文档与试点环境

---

## 3. 请 IT 提供的信息（清单）

1. **正式对接文档**：扫码登录流程、工号密码登录流程（如有）  
2. **测试环境**：UAT 应用 `AppKey/Secret` 或测试 CAS 地址（可仅内网访问）  
3. **回调地址登记规则**：是否允许 `http://127.0.0.1:8787/login/callback` 或需固定席位 IP（如 `http://10.x.x.x:8787/...`）  
4. **Token 有效期与刷新**：会话多久过期、是否支持 refresh  
5. **网络要求**：是否必须连 VPN、是否有 IP 白名单  
6. **联系人**：Next/钉钉应用审批与联调对接人  

---

## 4. 安全与范围

- 密钥、`AppSecret` 等 **不入前端代码仓库**，由席位本地配置文件或 IT 密钥管理下发（可参考现有 `data/sf-foc-config.local.json` 做法）。  
- 第一阶段仅 **气象席位值班使用**，用户规模小；权限模型暂区分「已登录即可用」，带班/值班员角色可在工作台内保留现有逻辑，后续再与 HR/岗位系统对齐。
